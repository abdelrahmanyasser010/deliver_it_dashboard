# Deliver It — Frontend Freeze

## حالة النسخة

هذه النسخة هي **مرجع المنتج الأمامي قبل بناء الـBackend**. الهدف منها تثبيت:

- الكيانات والحقول التي تحتاجها الواجهات.
- حالات الشحنة وانتقالاتها.
- تدفقات التشغيل والتحصيل والتسوية.
- الصلاحيات المرئية لكل دور.
- عقود الأوامر التي ستتحول إلى API Commands لاحقًا.
- Read Models التي تقرأ منها الصفحات والتقارير.

النسخة الحالية تستخدم Mock Gateway و`localStorage` فقط لمحاكاة قاعدة البيانات. لا يعتبر ذلك تخزينًا آمنًا أو بديلًا عن الـBackend.

---

## النتيجة المعمارية

أصبح التطبيق يعتمد على **مصدر حقيقة واحد** هو `DeliveryState` داخل:

```text
src/context/DeliveryDataContext.tsx
```

ويضم:

- الشحنات.
- المناديب.
- التجار.
- مهام الاستلام.
- دفعات التوزيع.
- تحديثات المناديب.
- دفعات الباركود.
- التسويات.
- القيود المالية.
- المحادثات.
- سجل العمليات.
- الفترات المالية المغلقة.

لا تحتفظ صفحات التشغيل بنسخ مستقلة من هذه البيانات. التفضيلات الشخصية فقط مثل الأعمدة والـSaved Views تبقى في `localStorage` بصورة منفصلة.

## نقطة استبدال الـBackend

العقد الرئيسي:

```text
src/application/delivery/contracts.ts
```

الربط الحالي:

```text
src/infrastructure/delivery/gateway.ts
```

حاليًا:

```ts
export const deliveryGateway = mockDeliveryGateway;
```

لاحقًا يصبح:

```ts
export const deliveryGateway = apiDeliveryGateway;
```

دون إعادة كتابة الصفحات.

يدعم العقد ثلاث طرق لتحديث الواجهة بعد تنفيذ الأمر:

1. `projection`: السيرفر يعيد Read Model محدثة.
2. `refresh`: الواجهة تعيد قراءة الـRead Model من السيرفر.
3. `applyLocally`: للـMock فقط؛ يطبق الـReducer المحلي لمحاكاة السيرفر.

منطق الأعمال المحلي موجود في:

```text
src/application/delivery/reducer.ts
src/application/delivery/workflow.ts
```

ويستخدم كمرجع لبناء قواعد الـBackend والاختبارات، وليس شرطًا أن يبقى مصدر القرار بعد الربط بالسيرفر.

## ربط أجزاء النظام

### الشحنة

أي تغيير في الشحنة ينعكس مباشرة على:

- الصفحة الرئيسية.
- جدول الشحنات وملف الشحنة.
- مركز العمليات.
- مركز الاستثناءات.
- أداء المندوب.
- أداء التاجر.
- التقارير.
- المحاسبة.
- التسويات.
- الإشعارات.
- سجل العمليات.

### الباركود

إغلاق الدفعة المكتملة:

- يحدث الشحنات المتوقعة.
- يسجل حدثًا لكل شحنة.
- يغلق الدفعة.
- يجعل الشحنات جاهزة للمرحلة التالية.

### الاستثناءات

لا يختفي الاستثناء بمجرد الضغط على «تم التعامل». يتم تنفيذ Resolution مرتبط بنوعه أو تسجيل سبب الإغلاق في سجل العمليات.

### التسوية

دورة التسوية:

```text
draft / underReview → approved → paid / reconciled
```

وعند الدفع:

- تحدث حالات الشحنات المالية.
- تسجل القيود.
- تحفظ مرجعية الدفع.
- يحدث رصيد التاجر.
- يسجل Audit Event.

## التقارير

التقارير لا تستخدم أرقامًا ثابتة. يتم اشتقاقها من نفس الشحنات حسب:

- اليوم.
- آخر سبعة أيام.
- الشهر الحالي.
- فترة مخصصة.

المقارنة تتم مع فترة سابقة مساوية في المدة. الضغط على المؤشر يفتح الشحنات التي كونت الرقم مع نفس التاريخ والفلاتر.

تعريف نسبة نجاح محاولة التوصيل:

```text
تم التسليم ÷ (تم التسليم + فشل التسليم + التأجيل + المرتجع)
```

## حدود الـMock الحالية

- `localStorage` ليس قاعدة بيانات.
- لا يوجد تزامن بين أجهزة أو مستخدمين.
- لا توجد Concurrency أو Transactions حقيقية.
- كلمات المرور والمصادقة ليست مطبقة.
- رفع الملفات والصور يحتاج Media Service.
- الموقع الحي يحتاج Mobile/Tracking Service.
- الإشعارات الفورية تحتاج WebSocket أو Push Service.
- التقارير الكبيرة يجب حسابها في Backend Read Models أو Analytics Store.

هذه الحدود مقصودة ولا تتطلب تغيير تصميم الصفحات عند بناء الـBackend.
