# تقرير تطبيق مراجعة v7 على FIX 365 Dashboard

## الحالة
تم تطبيق مراجعات Product/UI/Domain ذات الأولوية على نسخة الداشبورد المرفوعة، مع الحفاظ على بنية المشروع الحالية وعدم ربط Backend حقيقي في هذه النسخة.

## نطاق التعديلات الفعلية

### الشحنات والطباعة
- إضافة مكونات طباعة بوالص مستقلة عن شاشة الشحنات.
- إضافة CODE128 داخلي.
- دعم معاينة الطباعة بدل طباعة جدول الشحنات نفسه.
- تجهيز البنية لمقاسات البوالص وA4.
- تحسين عرض تفاصيل الشحنة والإجراءات التشغيلية.

### التصدير Excel/CSV
- إضافة `exportSpreadsheet.ts` كطبقة تصدير موحدة.
- تحويل تصديرات المستخدم النهائي إلى Spreadsheet/XLSX flow بدل CSV الخام الذي يفتح في عمود واحد.
- الإبقاء على CSV للاستخدامات التي تحتاج CSV فعلاً.

### مركز العمليات
- تحسين دورة استلام التجار وتأكيد الوصول وإسناد التوصيل واعتماد تحديثات المناديب.
- فصل تقرير المندوب عن الحالة الرسمية للشحنة.
- تقليل الاعتماد على تغيير حالة عام.

### المناديب
- توسيع نموذج المندوب ليقترب من Driver 360.
- فصل بيانات تشغيلية إضافية عن بيانات الحساب.
- إضافة مفاهيم السعة/الحالة/العهدة/الإدارة الآمنة للحساب.

### التجار
- توسيع نموذج التاجر باتجاه Merchant 360.
- إزالة منطق التسوية اليدوية كمبلغ حر من واجهة التاجر.
- إضافة ربط أفضل بالشحنات والتسويات والتواصل.

### المستخدمون والصلاحيات
- تعديل صفحة المستخدمين باتجاه Staff Users بدلاً من خلط جميع أنواع الحسابات.
- تحسين نموذج الأدوار والصلاحيات والحالات.

### المحاسبة والتسويات
- تحسين منطق مراجعة الإقفال وعدم التعامل معه كـChecklist يدوية فقط.
- تحسين عرض الأستاذ العام والتسويات والإجراءات المالية.
- تحسين فصل حالات الاعتماد والدفع.

### التقارير
- إضافة/تحسين Drill-down بدلاً من Toast-only في بعض التفاصيل.
- تحسين فتح تفاصيل الشحنة من التنبيهات والتقارير.

### الشات
- إضافة بنية UI لمرفقات الصور/الملفات ضمن تجربة الشات الحالية.

### الإعدادات والـAudit
- توسيع إعدادات مرتبطة بالطباعة والإشعارات والسياسات.
- تحديث أنواع/أوامر الـDelivery والـAudit لتغطية التعديلات.

## التحقق
- تم إجراء فحص Parse/Transpile لملفات TypeScript/TSX للتأكد من عدم وجود أخطاء Syntax.
- لم يتم اعتماد `npm run build` أو `npm run lint` أو `npm test` كـPassed في بيئة العمل الحالية لأن تثبيت `node_modules` غير مكتمل/غير موثوق.
- يجب تشغيل بوابات الجودة محلياً بعد `npm ci` أو `npm install` على جهاز التطوير.

## أوامر التحقق المطلوبة محلياً
```bash
npm ci
npm run lint
npm test
npm run build
```

## ملاحظة مهمة
هذه النسخة ما زالت Frontend/Mock-oriented. القواعد الحساسة مثل الصلاحيات، Allowed Transitions، العزل متعدد الشركات، التسويات المالية، Idempotency، الملفات، الإشعارات وExport Jobs يجب فرضها في Backend أيضاً قبل Production.
